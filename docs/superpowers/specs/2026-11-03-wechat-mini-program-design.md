# 年卡打卡微信小程序设计

## 意图

把现有年卡打卡网页迁移为微信小程序，并通过微信云开发保存用户数据，使同一微信用户在不同设备登录后能看到相同的设置和打卡记录。

## 当前情况

仓库目前是无框架的静态网页，由 `index.html`、`styles.css` 和 `app.js` 构成。年卡设置、月度目标、打卡记录、回本进度、补记/改日期/删除和 JSON 备份均在浏览器端完成。状态保存在 `localStorage`，网页没有用户身份或后端。JSON 备份包含 `settings` 和 `visits`。

## 目标

- 提供微信小程序版本，保留现有年卡记录和统计能力。
- 使用微信云开发身份识别用户，并将年卡设置与打卡记录保存到云端。
- 同一用户在不同设备使用时读取同一份云端数据。
- 支持将现有网页导出的 JSON 备份导入小程序。
- 保留数据备份导出能力，便于用户自行留存。

## 非目标

- 不建设独立服务器或网页端云同步。
- 现有网页继续作为独立的本地版保留，不读取或写入小程序云端数据。
- 不做多张年卡/家庭共享/多人协作。
- 不在本次加入微信支付、社交分享或订阅消息。
- 不承诺离线时跨设备同步；无网络时允许查看缓存，云端写入需要联网。

## 方案选择

1. **微信云开发（选择）**：小程序通过云函数获得微信用户身份，云数据库按用户保存数据。无需自建服务器，最适合当前单人工具和已确认的云开发方向。
2. **自建 API 与数据库**：可支持更多客户端和更灵活的服务端能力，但需要部署、维护和鉴权体系；当前没有后端，不作为首期方案。

## 设计

### 小程序端

- 新增原生微信小程序结构，使用 WXML、WXSS 和小程序 JavaScript API 重建现有单页界面与交互。
- 将纯计算逻辑（月份序列、月度统计、回本阈值）与视图/存储分开，尽可能复用其业务规则。
- `onLaunch` 初始化云开发；通过云函数取得当前用户标识，页面只调用封装的数据服务，不自行传入或选择其他用户标识。
- 启动时读取云端设置及记录；成功保存后更新本地页面状态。允许缓存最近一次加载的数据用于断网查看，但断网修改不作为首期支持功能。
- 每次小程序重新打开/进入前台时刷新云端数据；另一台设备已打开的页面不要求即时推送更新。
- 网页现有 JSON 备份可通过小程序文件选择能力导入；导入前预览记录数并明确提示“替换云端当前数据”，确认后一次性提交。导出生成相同兼容格式的 JSON。

### 云端数据

- 使用两个集合：`userSettings` 每位用户一条设置文档；`visits` 每次到场一条记录。
- 文档均带由云函数上下文确定的用户标识。客户端数据库权限不允许直接读取或写入集合；数据操作由云函数校验当前调用者并按其身份过滤。
- 设置文档保存 `price`、`startMonth`、`duration`、`monthlyTarget`、`feeA`、`feeB`、`monthTargets` 和更新时间。
- 打卡文档保存稳定 ID、日期和创建时间。添加、修改、删除均由云函数限定在当前用户记录范围内。
- 首次使用时若没有云端设置，使用仓库当前默认值；用户数据不做跨账号公开。

### 数据迁移

- 网页端现有 `localStorage` 不会自动出现在微信小程序中。用户在网页导出 JSON 后，在小程序中选择并确认导入，数据写入当前微信账号。
- 网页保留原来的本地存储行为，不与小程序账号同步；需要通过 JSON 备份在网页与小程序之间迁移数据。
- 云端非空时导入采用整体替换并二次确认，避免意外覆盖；日常打卡不执行整份数据覆盖。

## 约束与待配置项

- 发布前需要用户拥有并配置微信小程序 AppID，并在微信开发者工具中开通/绑定云开发环境。
- 云函数环境 ID、集合和访问规则需随代码提供清晰配置说明；真实 AppID 与环境凭据不提交到仓库。
- 小程序首次启动和每次云端读写都需要网络；云开发资源额度与部署状态由账号侧决定。

## 验收要点

- 新账号可使用默认年卡设置，添加打卡后刷新仍存在。
- 同一微信账号在另一台设备进入时可见同一设置和记录。
- 修改/删除记录和月度目标后，统计及回本进度一致更新。
- 可导入现有网页 JSON；导入确认会替换当前账号数据，取消则不变。
- 用户 A 无法读取或修改用户 B 的云端记录。
- 断网可查看最近缓存，并对云端操作给出清楚失败反馈，不显示未保存成功。
